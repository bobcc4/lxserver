# Web 播放器使用指南

LX Music Sync Server 在路由 `/music` 提供了一个现代化的 Web 音乐播放器。可以实现远程播放、搜索和多端同步交互。

## 核心功能清单

当前 Web 播放器支持的功能：

- **搜索与音源**：支持五大音乐平台搜索，支持自定义上传 JS 脚本或导入 URL 扩展音源。支持搜索专辑、搜索歌手并进行收藏。
- **播放控制**：多音质选择（128k/320k/FLAC/Hi-Res）与音质失败自动降级。支持调速（0.5x-2.0x）、淡入淡出、播放进度记忆。
- **用户交互**：支持快捷键、PWA、歌曲评论、多种播放模式（单曲循环、列表循环、随机等）。
- **同步功能**：支持读取和显示用户保存在服务端的收藏和歌单，支持热搜显示、批量下载操作。
- **协议支持**：全面适配 **Subsonic** 协议，支持音流、Feishin 等各类 Subsonic 客户端连接，实现资源互通。
- **UI 体验**：底部音频波形显示、内置 5 种主题、睡眠定时器。
- **歌词扩展**：支持显示翻译及罗马音，支持卡拉OK逐字高亮渲染，支持分享歌词图片。

---

## 访问播放器

默认访问地址：
**示例**：`http://IP:9527/music`

如果管理员在服务器环境变量中设置了 `ENABLE_WEBPLAYER_AUTH = true`，则每次打开该页面时必须输入设定的 `WEBPLAYER_PASSWORD` 才能进入播放界面。

## 核心机制说明

Web 播放器对于请求和缓存采用了以下机制：

### 1. 音源脚本的账号隔离与管理机制

为了确保多用户之间互不干扰，自定义音源只对当前已登录的同步用户开放，并按账号进行隔离：

- **账号独享存储**：上传或导入的 JS 音源脚本保存在 `data/users/source/{用户名}` 目录。
- **独立启用状态**：每个用户只能查看、启用、禁用和删除自己的自定义音源。
- **独立排序**：拖拽音源列表后的顺序只保存到当前用户目录，不影响其他用户。
- **登录要求**：未登录同步账号时不能读取或管理自定义音源。


### 2. 音质自动降级

在前端选择了**默认音质**后（例如选了 320k），如果解析引擎在获取目标音质时失败：
系统会自动按照 `flac -> 320k -> 192k -> 128k` 的降级顺序往下尝试。直到成功获取到能够正常解析并播放的低一级音质为止，从而尽量避免无法播放的问题。

### 3. 数据层代理转发

为了避免浏览器直接获取在线音乐链接时可能遇到的跨域阻断（CORS）：
如果在设置中开启了**播放音乐代理** 或 **下载音乐代理**：

- 前端浏览器将不再直接请求真实的音乐直链，而是请求你搭建的这个 LX Node 服务端。
- 服务端在后台获取到真实的音乐数据流后，再直接分包转发给你的前端浏览器，以此绕开跨域限制。

此外，Web 播放器还支持**自动代理 (Auto Proxy)** 功能：
- **混合内容保护**：当你将服务部署在 HTTPS 协议下时，浏览器出于安全考虑会默认阻断 HTTP 协议的媒体资源请求（即“混合内容”限制）。
- **智能识别**：开启“自动代理”后，如果系统检测到当前身处 HTTPS 环境，而获取到的音源链接是 HTTP 协议，会自动将该请求转由服务端代理。这种模式既解决了 HTTPS 下的播放兼容性问题，又能在音源本身支持 HTTPS 时保留直连的响应速度。

### 4. V2 存储与三级缓存机制

V2 不再为每个用户维护独立的物理 `/cache` 和 `/music` 目录。两者仍作为用户可见的**逻辑分类**存在，但条目关系统一保存在 SQLite 中，音频实体则进入全局内容寻址仓库：

| 路径 | 用途 |
| --- | --- |
| `/server/data/media/media.db` | 用户、逻辑分类、歌曲信息和音频哈希之间的索引 |
| `/server/data/media/objects` | 按 SHA-256 内容哈希保存的音频实体 |
| `/server/data/media/lyrics` | 按音频哈希保存的外置歌词 |
| `/server/data/media/covers` | 按用户保存的封面缓存 |
| `/server/data/media/temp` | 下载和写时复制过程中的临时文件 |

#### 逻辑分类

- **缓存**：播放时自动保存的临时媒体条目，可由容量限制和缓存清理功能回收。
- **音乐**：用户明确下载到服务器或从缓存转入本地音乐库的持久条目，不会被普通缓存淘汰自动删除。
- **缓存转音乐**：只调整当前用户在 SQLite 中的逻辑归属；底层音频内容不需要重复复制。
- **跨用户去重**：多个用户引用完全相同的音频内容时，只保存一份物理对象，各用户的文件名、分类和歌单仍相互独立。

#### 播放缓存层级

- **第一级 (本地媒体对象)**：优先查找当前用户在 SQLite 中可用的音乐或缓存条目。命中后由服务端直接传输对象仓库中的文件，并支持 `206 Partial Content` 和进度拖拽。
- **第二级 (链接缓存)**：浏览器 LocalStorage 会保存近期解析成功、可能带时效 Token 的音乐直链。在有效期内再次播放时，可复用已有链接。
- **第三级 (实时解析)**：本地媒体未命中且历史链接失效时，系统重新调用当前用户可用的自定义音源获取播放地址。

删除缓存或音乐条目时，系统先删除当前用户的数据库引用。只有最后一个引用被删除后，底层音频对象才会被回收，因此不会误删其他用户仍在使用的相同文件。部署时只需持久化 `/server/data`，不要再挂载旧版 `/cache` 和 `/music` 目录。

完整的数据结构、音源分享、歌单分享和 Subsonic 使用说明见 [V2 功能与使用场景](/guide/v2-features)。

---

> [!CAUTION]
> V2 不支持从旧版目录结构直接覆盖升级。请先备份旧数据，再使用空的 `/server/data` 目录首次启动。播放器中的清理操作会真实删除当前用户的媒体引用和浏览器链接缓存，操作前请确认所选逻辑分类和歌曲。
