# V2 功能介绍与使用指南

V2 面向 NAS、家庭服务器和多用户私有音乐服务场景。它将 LX Music 数据同步、Web 播放器、音源管理、用户间歌单分享和 OpenSubsonic 接口集中在同一个服务中，并使用 SQLite 与内容寻址对象仓库统一管理下载和缓存的音频。

> [!CAUTION]
> V2 改变了持久化数据结构，不支持从旧版直接覆盖升级。部署前请备份旧数据，删除旧容器数据、旧音乐和缓存文件，再使用空的 `/server/data` 目录启动 `bobcc4/lxserver:V2`。

## 一、V2 的核心变化

### 1. SQLite 媒体索引

V2 不再把每个用户的媒体索引分散保存在 JSON 文件中，而是统一写入：

```text
/server/data/media/media.db
```

数据库保存用户、逻辑目录、歌曲标识、音质、文件名、歌词状态、封面状态和音频对象哈希等关系。SQLite 文件位于 `/server/data` 持久化卷中，容器重建后仍可恢复下载队列所依赖的媒体索引。

### 2. 全局不可变音频仓库

音频按 SHA-256 内容哈希存储：

```text
/server/data/media/objects/<哈希前缀>/<sha256>.<扩展名>
```

这带来以下行为：

- 两个用户下载到完全相同的音频内容时，物理磁盘只保存一份文件。
- 每个用户仍拥有独立的歌曲引用、逻辑文件名、缓存/音乐分类和歌单数据。
- 删除一个用户的歌曲只删除该用户的引用；其他用户仍在使用时不会删除物理音频。
- 最后一个引用被删除后，系统才回收音频对象和对应的外置歌词。
- 写入元数据或嵌入歌词时使用写时复制，不会直接修改其他用户正在共享的对象。

相关持久化目录：

| 路径 | 用途 |
| --- | --- |
| `/server/data/media/media.db` | SQLite 媒体索引 |
| `/server/data/media/objects` | 内容寻址音频对象 |
| `/server/data/media/lyrics` | 按音频哈希保存的外置歌词 |
| `/server/data/media/covers` | 按用户保存的封面缓存 |
| `/server/data/media/temp` | 下载和写时复制的临时文件 |

### 3. 账号数据仍然隔离

全局仓库只复用相同的物理音频内容，不会合并用户数据。以下内容仍按同步用户名隔离：

- LX Music 同步数据与快照
- 我喜欢的音乐和用户歌单
- 收藏的歌手与专辑
- Web 播放器设置
- 本地音乐的逻辑条目和文件名
- 歌单分享收件箱

## 二、三类密码与权限

| 凭据 | 用途 | 是否可管理服务器 |
| --- | --- | --- |
| 管理后台密码 `FRONTEND_PASSWORD` | 登录管理后台、修改系统配置、授权音源分享 | 是 |
| 同步用户名和同步密码 | LX Music 同步、Web 播放器用户登录、Subsonic 登录 | 否，普通用户只能访问自己的数据 |
| Web 播放器访问密码 `WEBPLAYER_PASSWORD` | 可选的 `/music` 页面入口保护 | 否，它不能代替同步账号 |

普通用户只需要知道自己的同步用户名和同步密码。管理员无需把管理后台密码交给普通用户。

## 三、管理员共享音源

音源分享适合由管理员维护一份可用的自定义音源，再授权给一个或多个普通用户使用。普通用户不需要重复上传同一脚本，也不需要知道管理后台密码。

### 使用步骤

1. 管理员打开 Web 播放器 `/music`。
2. 登录拥有该音源的同步账号。
3. 进入“设置”中的自定义音源管理，上传或通过 URL 导入音源脚本。
4. 先启用音源并确认状态正常。
5. 点击该音源的分享按钮。首次操作会要求输入管理后台密码进行授权。
6. 选择指定用户，或者选择“共享给全部用户”，然后保存。
7. 接收用户重新打开或刷新音源列表后，即可看到共享音源。

### 权限与行为

- 只有通过管理后台密码授权后才能新增、修改或取消音源分享。
- 可以共享给指定用户，也可以共享给当前和以后创建的全部用户。
- 接收方看到的共享音源是只读项，不能修改或删除源脚本。
- 用户自己的同 ID 音源优先，系统不会再重复展示共享项。
- 音源脚本仍由所有者集中维护；所有者更新脚本后，接收方使用的是更新后的版本。
- 删除源时会自动取消相关分享。
- 新建分享时要求源已启用。源被停用或运行失败后，接收方也无法继续通过它解析歌曲。

### 安全建议

自定义音源本质上是服务端执行的 JavaScript。只导入可信来源，并尽量使用默认的受限运行模式。需要不安全 VM 模式的脚本还必须由管理员开启 `system.allowUnsafeVM` 并单独确认，不应因为“共享方便”而降低脚本审查标准。

## 四、所有用户之间分享歌单

歌单分享不要求发送者是管理员。任意两个同步用户都可以互相分享，但双方必须主动开启“允许用户间分享歌单”。这项双向开关用于避免普通用户在不知情时收到分享请求。

### 开启和发送

1. 发送方和接收方分别登录 Web 播放器。
2. 双方进入“设置 -> 歌单分享”，开启“允许用户间分享歌单”。
3. 发送方在左侧用户歌单旁点击分享图标。
4. 输入接收方用户名并发送。
5. 接收方会看到“待处理分享”提示，可选择接受或拒绝。

### 接受后的结果

- 接受后会创建一个独立歌单，名称格式为“原歌单名（发送者 分享）”。
- 接收方得到的是发送时的歌曲快照，不是与发送方持续绑定的实时镜像。
- 接收方之后可以自行改名、增删歌曲，不会反向修改发送方歌单。
- 接受操作会生成同步快照，随后可同步到接收方的其他 LX Music 客户端。
- 拒绝只会移除待处理请求，不会创建歌单。

### 边界和限制

- 目前分享入口针对用户创建的歌单；空歌单、默认列表和“我喜欢”不能通过该入口发送。
- 不能分享给自己。
- 对方未开启分享时，发送方会收到“不接受分享歌单”的提示。
- 待处理请求保留 30 天，每个用户最多保存 100 条待处理分享。
- 同一发送者再次分享同一个歌单时，会更新尚未处理的快照，不会重复堆积请求。
- 分享的是歌曲信息和平台 ID，不会在接受时立即复制或下载音频。
- 如果歌曲没有可用的平台 ID，或接收方没有可用音源，该歌曲可能只能显示而无法在线解析。

### 与 V2 去重仓库的关系

歌单分享本身几乎不占用音频空间。接收方之后选择下载歌曲时，如果下载结果与仓库中已有音频字节完全一致，V2 会复用现有对象；不同音质、不同平台版本或元数据内容不同的文件会产生不同哈希，因此仍可能保存为不同对象。

## 五、Subsonic 搭配音流

V2 提供兼容 Subsonic 1.16.1 与 OpenSubsonic 扩展的接口，可供音流、Feishin 等客户端读取用户歌单、封面、歌词并播放音乐。

### 服务端设置

登录管理后台，在系统配置中确认：

- “启用 Subsonic 服务”已开启，默认值为开启。
- Subsonic 访问路径默认为 `/rest`。
- 在线搜索按需求选择“自动兜底”“本地与在线融合”或“仅本地”。
- 默认在线平台可填写 `wy,tx,kw,kg,mg` 的任意组合。
- 需要翻译歌词时开启“歌词翻译支持”。

公网使用时建议在反向代理中启用 HTTPS，并确保 `/rest` 路径和 Range 请求没有被拦截。

### 音流连接参数

在音流中新增 Subsonic/OpenSubsonic 服务器：

| 音流字段 | 填写内容 |
| --- | --- |
| 服务器地址 | 通常填写 `http://NAS-IP:9527` 或 HTTPS 域名 |
| API 路径 | 客户端自动追加时无需填写；需要完整路径时使用 `/rest` |
| 用户名 | 同步用户名，例如普通用户自己的账号 |
| 密码 | 该用户的同步密码 |

不要填写管理后台密码或 Web 播放器访问密码。Subsonic 通过请求中的用户名识别用户，因此即使默认启用了根地址，也不需要把用户名追加到 URL 中。

连接测试也可以直接访问：

```text
http://NAS-IP:9527/rest/ping.view?u=<用户名>&p=<密码>&v=1.16.1&c=test
```

正常响应的 `status` 为 `ok`。实际客户端通常使用 token + salt 认证，不会长期发送明文密码。

### 在音流中可以访问的内容

- 默认列表、“我喜欢”和用户创建的歌单
- 收藏专辑、收藏歌手以及相关歌曲
- 歌曲、专辑和歌手搜索
- 封面、传统歌词和 OpenSubsonic 结构化歌词
- 音频流、下载、Range 断点播放
- 随机歌曲、相似歌曲、热门歌曲和分类浏览
- 歌单歌曲增删等客户端支持的更新操作

音频由 lxserver 代理转发给客户端，源站 URL 不会直接暴露给音流。服务端会处理重定向、Range、上游代理和失效链接重新解析。

### 搜索语法

| 输入 | 效果 |
| --- | --- |
| `周杰伦` | 按后台配置的默认模式搜索 |
| `local:周杰伦` | 只搜索当前用户的本地歌单与收藏库 |
| `online:周杰伦` 或 `net:周杰伦` | 强制在线搜索默认平台 |
| `tx:周杰伦` | 只使用腾讯源在线搜索 |
| `wy:周杰伦` | 只使用网易源在线搜索 |
| `kw:` / `kg:` / `mg:` | 分别指定酷我、酷狗、咪咕 |

英文冒号 `:` 和中文冒号 `：` 都支持。部分第三方客户端会在发送请求前自行处理搜索字符串；若平台前缀无效，应先确认客户端是否把原始查询完整传给了服务端。

### 在线搜索模式

| 模式 | 行为 |
| --- | --- |
| `fallback` | 先查用户本地数据，结果不足时使用在线平台补足 |
| `merge` | 同时返回本地与在线结果，本地结果优先 |
| `local_only` | 完全关闭无前缀查询的在线补充 |

带 `online:` 或具体平台前缀的查询会强制在线搜索，不受默认模式限制，但仍要求后台已加载可用音源。

### 音质与歌词

Subsonic 客户端通过 `maxBitRate` 表达播放上限。当前映射为：

- 小于 `320`：请求 `128k`
- `320` 到 `999`：请求 `320k`
- 未限制或不小于 `1000`：请求 `flac`

Web 播放器中的 24bit、Hi-Res、空间音频和母带选项不等同于 Subsonic 的码率上限；需要这些音质时建议先在 Web 播放器下载到服务器，再通过本地媒体条目播放。

歌词同时提供传统 `getLyrics`、`getLyricsBySongId` 和 OpenSubsonic 结构化歌词接口。客户端是否显示逐行歌词、翻译或罗马音，仍取决于客户端实现。

## 六、推荐的组合工作流

一个典型的家庭多用户场景如下：

1. 管理员维护 TX、WY 等自定义音源，并共享给家庭成员。
2. 用户 A 制作歌单并分享给用户 B。
3. 用户 B 在 Web 播放器接受歌单，歌单进入自己的同步空间。
4. 用户 B 使用自己的同步账号连接音流，即可看到并播放该歌单。
5. 用户 B 下载歌曲到服务器时，V2 对相同内容进行全局去重，但歌单和本地音乐条目仍属于用户 B。

这套流程把“谁维护音源”“谁拥有歌单”“谁使用客户端”和“磁盘上保存几份音频”分开管理，适合管理员集中维护、普通用户独立使用的 NAS 环境。

## 七、常见问题

### 音流可以连接，但歌曲点开后跳到下一首

通常表示歌曲信息可见，但服务端未能解析出可播放 URL。检查共享音源是否启用、源脚本是否有效、对应平台是否需要登录信息，以及管理后台的 Subsonic 调试日志。

### 音流看不到刚接受的歌单

先在 Web 播放器确认歌单已创建，再在音流中手动刷新服务器或重新同步资料库。接受的是独立快照，发送方后续修改不会自动更新。

### 音流没有显示歌词

确认服务端已开启歌词翻译支持并且歌曲能获取歌词。不同客户端可能只实现传统歌词或只实现 OpenSubsonic 结构化歌词，应同时检查客户端能力。

### 普通用户需要管理员密码吗

不需要。普通用户使用自己的同步账号即可连接 Web 播放器、LX Music 和 Subsonic。只有修改系统配置、授权音源分享或使用其他管理功能时才需要管理后台密码。
